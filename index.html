Why api-scorecard

Ship APIs that AI agents
can actually use

Most OpenAPI specs are written for humans. AI agents have different needs — and most specs fail silently.

⚡

Instant feedback

Run against any OpenAPI 3.x spec and get a scored report in milliseconds. No account, no upload, no waiting.

🤖

AI-first scoring

Dimensions are weighted for what LLMs and agents actually need: semantic operation IDs, error schemas, intent descriptions.

🎯

Actionable issues

Every failing check includes the exact JSON path and a plain-English explanation so you know what to fix and where.

🔌

CI/CD ready

Structured exit codes (0 pass / 1 error / 2 fail) and --json output make it trivial to gate deploys on API quality.

📦

Zero dependencies on infra

Pure Python CLI. Runs locally, in Docker, or in any CI runner. Your spec never leaves your machine.

📊

Letter grades at a glance

A single A–F grade tells the whole story. Drill down per-dimension to understand exactly where quality is lost.

Comparison

api-scorecard vs Jentic

Both tools aim to make APIs work better with AI — but they solve fundamentally different problems at different points in your workflow.

Feature api-scorecard Jentic
Primary purpose Score & improve OpenAPI specs for AI-readiness Discover & execute APIs at runtime for AI agents
When you use it Before & during API development (design time) When building AI agents that call APIs (runtime)
Input Local OpenAPI / Swagger YAML or JSON file Natural language query to discover APIs in registry
Output Scored report with letter grade + actionable fixes Executable workflow / API call ready for an agent
Open Source Fully open source (MIT) SDK open source, platform is SaaS
Runs locally 100% offline — spec never leaves your machine Requires internet access to Jentic cloud registry
CI/CD integration Exit codes + JSON output, drop into any pipeline Not designed for CI quality gates
Actionable fix guidance Exact JSON path + plain-English recommendation per issue No spec improvement guidance
Multi-dimension scoring 6 weighted dimensions with per-dimension grades No quality scoring model
API execution / calling Analysis only — does not call your API Core feature — finds and executes API calls for agents
API registry / discovery Works on a single spec you provide Searches a large registry of third-party APIs
Requires account / login No — zero signup, just install and run Free tier available, full registry needs API key
Installation pip install reuse-api pip install jentic
Best used by API developers, platform engineers, DevOps teams AI agent developers integrating third-party APIs

They're complementary, not competing

Use api-scorecard to verify your OpenAPI spec is high-quality and AI-ready. Then use Jentic to let agents discover and call it at runtime. A higher api-scorecard grade means Jentic agents can use your API more reliably — fewer hallucinations, better tool selection.

Get started

Up and running in 30 seconds

No account. No config. Just point it at an OpenAPI spec.

# Install
uv pip install -e git+https://github.com/SheepSeb/reuse_api

# Score your spec
api-scorecard score path/to/openapi.yaml

# Try the built-in demo
api-scorecard demo
# Clone & install
git clone https://github.com/SheepSeb/reuse_api
pip install -e ./reuse_api

# Score your spec
api-scorecard score path/to/openapi.yaml

# JSON output for CI
api-scorecard score openapi.yaml --json

Exit codes

0 Score ≥ 60 — passing
1 Error reading or parsing the spec
2 Score < 60 — failing grade

Gate your CI pipeline on API quality:
api-scorecard score openapi.yaml || exit 1
